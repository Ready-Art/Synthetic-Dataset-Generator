# 📝 Changelog — v11.x and earlier

Newest first. [v12.x](changelog-v12.md) holds the current series.

### v11.10.0
- **Non-Latin script check** — a model trained on more than one language occasionally drops a stray glyph into an otherwise English reply: a Chinese character, a Cyrillic word, a Greek letter used as decoration, an emoji. A phrase list cannot catch those (there is no fixed phrase to list), and an LLM round trip per reply would be expensive. The new check is **purely character-class based**: a Unicode range **allow-list**, so it costs nothing, needs no model and no network, and cannot miss a script nobody thought to list
- **Allow-list, not block-list** — a character is accepted when it is Latin script (any accent or extension, including the ligatures), a digit, whitespace, or one of the punctuation/symbol blocks a roleplay reply legitimately uses (curly quotes, dashes, ellipses, bullets, arrows, mathematical operators, box drawing, a star or a heart). Everything else is flagged — Chinese, Japanese, Korean, Cyrillic, Greek, Arabic, Hebrew, Devanagari, Thai, the emoji planes — because anything outside Latin is, by definition, not Latin. Accented Latin (`Café`, `naïve`, `straße`), curly quotes and guillemets all pass, so the check does not fight ordinary English prose
- **One row per script, not per character** — a reply that is a whole sentence in another script reports one entry per distinct script (with the sentence that holds the first offending character), so the dashboard is readable and the fix instruction is not repeated hundreds of times. `text.isascii()` is the fast path, so a pure-ASCII reply costs a single method call
- **What happens on a hit** — assistant answers are regenerated with one fix appended to the system prompt (the same shape as refusal/slop/OOC drift), and once `detection.non_latin.fixes` is exhausted the turn fails for that attempt and a fresh attempt starts, so a permanently stray reply is never written to the dataset. The generated question, the user continuation and opening-mode greetings/first lines are **re-rolled** instead (they are authored dataset text, not rewritable prose). Off by default, so existing output is unchanged
- **Configuration** — `detection.non_latin.enabled` (off by default) and `detection.non_latin.fixes` (one instruction per retry round; empty falls back to the built-in `generation.DEFAULT_NON_LATIN_FIX`, so switching the check on works without authoring a list). The Config Editor Detection tab gains a **Non-Latin Script Check** panel; the main window gains a **Non-Latin** metric card, a **Recent Non-Latin** issue panel on the Totals and per-API tabs, and a `Non-Latin` series in the issue graph. Both counters are persisted in the generation state file
- **Wiring** — `detection.py` (`is_non_latin()`, `find_non_latin_characters()`, `NON_LATIN_SCRIPT_RANGES`, `LATIN_ALLOWED_PATTERN`), `generation.py` (`DEFAULT_NON_LATIN_FIX`, the answer retry branch, the question/continuation/opening-mode re-roll, worker kwargs), `generate.py` (config read + worker kwargs + metric card + issue panel), `config/config.yml` (new defaults), `config_editor.py` (Detection tab panel + save/load/toggle), `app_state.py` (counters, recent lists, timestamp key), `dashboard.py` (metric label, panels, graph series). Guarded by `tests/test_non_latin.py`

### v11.9.0

- **Dataset variables in `input/questions.txt`** — a questions-file line is authored text, so it now accepts the same `{{ds:alias}}` placeholders the Datasets tab maps, and **one alias value can be appended to every line** instead of being written into each one. Two new settings: `prompts.questions_dataset.append_alias` (a single bare alias; empty means "placeholders only, append nothing") and `append_separator` (the text placed between the line and the appended value, default two newlines). The Config Editor gains a **Questions File Dataset Variables** panel on the Prompts tab, where the separator is shown escaped (`\n`) because a single-line field cannot hold a real newline
- **Same row, same task, same identity** — the value is expanded by the worker at the point where it already holds that task's frozen binding, through `dataset_tasks.render_question_task()` / `dataset_templates.render_question_line()`. The placeholder and the appended value therefore always come from the same dataset row, the task's ID, file name and index are untouched (so retries and resume keep working), and substitution is single-pass — a cell containing `{{ds:other}}` or `{context}` is inserted literally
- **Failures are loud, not silent** — an unmapped alias fails the task instead of reaching the model as literal text, `{{ ds:name }}` with spaces is a malformed placeholder, and an empty appended value appends nothing rather than leaving a dangling separator. `append_alias` needs the questions file on: the editor refuses to save it otherwise, and Start logs a warning and ignores a hand-edited value
- **Chunk-mode source `.txt` files are deliberately excluded** — a chunk is cut at a random character offset, so a placeholder there could be sliced in half and reach the model as literal garbage. Dataset variables belong in the questions file or in an authored prompt
- **A dataset-free run is byte-identical to before** — with no enabled sources the line is used exactly as read and nothing is appended. `tests/test_dataset_compatibility.py` runs the real worker twice per scenario and requires identical requests, now including a questions-file scenario that compares placeholder-plus-append against the same text typed in by hand

### v11.8.1
- **Judge priority range is now -10 to 10** — v11.8.0 shipped the field as 0-99, which made the most useful half of vLLM's range unreachable: lower means earlier handling, so the values that actually push the judge to the front of the queue are the negative ones. The range is now **-10 to 10** — **-10 is the highest priority**, `0` is vLLM's default, **10 is the lowest** — and every negative value passes through unmodified instead of being clamped up to `0` (v11.8.0's `max(0, ...)` silently demoted a judge the user had deliberately put first). The narrow window is deliberate: a handful of steps either side of the default is all a judge needs, and a tight bound cannot be mistyped into a runaway value. The spinbox, the save clamp and the validation assert all moved together, and the tests now walk both ends of the range (`-10` and `10` sent as-is, the negative half `-10/-7/-3/-1`, and `-99→-10` / `11→10` clamping) so a 0-floor cannot creep back in

### v11.8.0
- **vLLM request priority for the quality judge** — vLLM's OpenAI-compatible server accepts a top-level `priority` integer (lower means earlier handling) for priority scheduling. The judge's requests are low-volume but bursty, so a high number parks them behind the generation traffic instead of competing with it. Two new Quality Scoring settings: **Send vLLM priority with judge requests** (`quality.judge_priority_enabled`, **off by default**) and **Judge Priority** (`quality.judge_priority`, default `0`; the range was widened to -10..10 in v11.8.1)
- **Opt-in twice over, on purpose** — `priority` is not part of the OpenAI schema. A backend that does not know it (OpenAI, Anthropic, llama.cpp, most hosted gateways) rejects the unknown field outright, and vLLM itself raises an error for any priority other than `0` when the served model does not use priority scheduling. So the toggle defaults to off (the field is never sent at all; the payload is byte-identical to v11.7) and the value defaults to `0`, which every vLLM server accepts. The value is clamped to a fixed range, so a hand-edited `config.yml` cannot break a run (see v11.8.1 for the current bounds)
- **It rides on every attempt** — the field is merged into the request body once, so the transient retries, the format-repair rounds and the `response_format`-fallback request all keep the same priority and a retried judge request does not lose its place in the queue
- **Configuration Editor** — the Quality Scoring section gains the checkbox plus a spinbox that is disabled while the toggle is off (the value is kept, not reset, so re-enabling restores it)
- **Wiring** — `quality.py` (`judge_priority_enabled()`, `judge_priority()`, `_judge_priority_field()`, `JUDGE_PRIORITY_MIN` / `JUDGE_PRIORITY_MAX`, merged into the judge payload in `_call_logic_judge_once()`), `config/config.yml` (two new defaults), `config_editor.py` (checkbox + spinbox + `_toggle_judge_priority_field()` + save/load/validate). Guarded by the new priority cases in `tests/test_quality_json_robustness.py` and `tests/test_quality_judge_settings_ui.py`

### v11.7.2
- **The missing-quotations check no longer goes blind on contractions** — a report that mark-less spoken lines were still reaching the dataset, and that a downstream cleaner was removing ~18% of records (`330 conversations / 60 removed`) for containing no quotation marks at all, traced back to the v11.7.1 detector's guard. `is_missing_quotation()` bailed out if the reply contained **any** quote-like glyph, and that list included the plain apostrophe `'` and `’`. Ordinary English prose is full of contractions and possessives, so `It's not funny she says`, `She doesn't care, he said` and `Melody's hand trembles as she speaks` all disabled the check entirely: the experiment appeared enabled but effectively never fired on realistic text, and the replies were written to the dataset verbatim. The detector now discounts **word-internal** apostrophes before testing for quote glyphs — a contraction or possessive is not a quotation mark, while genuine single-quoted dialogue (`'Its funny,' she says`) still counts as quoted. The rule is defined **once**, in the new `detection.has_dialogue_quote_marks()`, which `is_missing_quotation()` calls. A **plural possessive** (`dogs'`, `the clocks' hands` — apostrophe after the final word character) is deliberately left counted, because it is indistinguishable from a closing single quote; that direction only *suppresses* the check (no pointless retry, turn kept), which is the safe failure mode. Guarded by new apostrophe-positive and `has_dialogue_quote_marks()` cases in `tests/test_missing_quotations.py`. Note the check remains **opt-in** (`generation.retry_missing_quotations`, off by default), so this fix only takes effect on runs that enable it
- **Wiring** — `detection.py` (`has_dialogue_quote_marks()` + `_APOSTROPHE_IN_WORD_RE` + `_DIALOGUE_QUOTE_MARKS`; `is_missing_quotation()` calls the helper instead of its inline `any(mark in text ...)` guard). No config, GUI or call-site change: the signature, label, snippet, word-count floor and attribution-verb list are all unchanged, so the retry policy and prefix-cache behaviour are byte-identical to v11.7.1

### v11.7.1
- **Experiment: Retry missing quotations** — Sometimes the model writes a spoken line with its quotation marks missing ENTIRELY: instead of `"Its funny," she says` it emits `Its funny she saystext`. The existing *incomplete-quote* check only ever saw UNBALANCED quotes (an odd count or mismatched openers/closers), so a reply that dropped every mark was written straight to the dataset as narration. A new `detection.is_missing_quotation()` flags a reply that (a) contains NO quotation glyph of any kind (straight `"`/`'` or curly `‘ ’ “ ”`), (b) has enough words to be narration, and (c) carries a speech-attribution verb (`says`, `said`, `whispered`, `told`, `asked`, …). When the new GUI toggle **Experiment: Retry missing quotations** (`generation.retry_missing_quotations`, off by default) is on, such an answer is sent back to the SAME main API slot that produced it for one retry (mirroring Regex Watch: the same slot rewrites in its own voice, no fixer slot); if the mark-less reply comes back again the best-effort answer is kept rather than dropped. It runs only after every other check has passed, is deliberately not added to the system prompt so prefix-caching servers keep their cache, and when off the pipeline is byte-identical to v11.7
- **Wiring** — `generation.py` (`worker` kwarg `retry_missing_quotations_local`, the check inside `generate_answer_with_retries()`, and the per-turn logic-gate retry inherit it), `generate.py` (reads `generation.retry_missing_quotations` at run start and passes it as a worker `kwargs=` entry), `config/config.yml` (new default), `config_editor.py` (Generation tab checkbox + save/load). Guarded by `tests/test_missing_quotations.py`

### v11.7.0
- **The absolute-trailer detector no longer fires on ordinary commas** — a report that generated text ending a line of dialogue on a comma (`"This is text,"`) was being rewritten turned out to be a real false-positive class. scotoma's `trailer_rate.py` requires a comma-appended segment to be **verbless** (no finite verb, no speech verb) and to carry a predicate signal (a body noun, an `-ing` participle or an `-ly` adverb); the first port kept the predicate test and dropped the verbless one, so every ordinary clause after a comma — `the man said`, `the boat is leaving`, `the door is open` — read as an absolute. The detector now enforces both tests, plus a third guard: a comma that *directly follows a speech verb* (`"...she said, turning away."`) opens the narration after the dialogue and is not a trailer either. The construction is defined **once**, as `style_metrics.TRAILER_PATTERN`, and both `config/config.yml` and `detection.DEFAULT_REGEX_WATCH_PATTERNS` mirror that exact string (`tests/test_regex_watch.py` asserts all three are identical), so the metric and the rewrite can never drift apart. It also now catches participle trailers it previously missed (`steam curling upward`). Regression cases are asserted in both `tests/test_style_metrics.py` and `tests/test_regex_watch.py`
- **Style metrics ported in from the scotoma analysis layer** — a new dependency-free `style_metrics.py` measures the style/quality signals scotoma worked out and calibrated against a human null: comma habits, tail-end positivity lift, narration share, interiority density, long-range grounding, coherence defects (script mix, foreign articles, determiner stutter, duplicate sentences), narration-only negation density/runs, denial-then-correction couplets, comma-appended absolute trailers, and turn-final question handback. It imports nothing project-local and nothing third-party, so it unit-tests headless (`tests/test_style_metrics.py`, 58 checks)
- **Two new Regex Watch patterns** — the two tic shapes scotoma isolated now ship as defaults (eight total, was six): **denial-then-correction** (`"It wasn't anger. It was fear."` — the shape the whole scotoma project was built around, which the existing six rhetorical-pivot patterns did not cover) and the **comma-appended absolute trailer** (`"...her lips parted"`; measured teacher 11.8% of sentences vs human 2.5%, rewrite fraction 0.79). The trailer pattern is the verbless-absolute test scotoma used — see the fix note above; an ordinary clause or a dialogue-closing comma never matches it. `config/config.yml` and `detection.DEFAULT_REGEX_WATCH_PATTERNS` stay in sync, so "Restore Defaults" rolls both back together. `question_handback` is deliberately NOT a regex — it is positional ("final sentence ends on ?"), which a whole-reply regex cannot express; it lives in `style_metrics.question_handback()` instead
- **New opt-in `tic_density` quality dimension** (`quality.tic_dimension`, off by default) — a heuristic-only 0–100 score over the assistant turns built directly from the style metrics: denial-correction couplets in >20% of turns (−20, `denial_correction_tic`), negation runs in >30% (−15, `negation_runs`), comma clause-stacking (mean 3+-comma sentence share >20%, −10, `comma_clause_stacking`), stacked qualifiers in >15% (−15, `qualification_stack`), formulaic warm/significance closers (clamped tail lift ≥3.0, −10, `formulaic_warm_closer`), and shallow narration (>40% asterisk narration with <1 interiority cue per 100 words, −10, `shallow_narration`). It is registered as a *measured* heuristic (in `HEURISTIC_DIMENSIONS`, not `LLM_DIMENSIONS`), so the judge never fabricates a number for it. Off by default like the roleplay dimensions, so existing composite scores stay byte-comparable; when on it joins the composite, the Quality tab (the tab is dynamic — no layout code changed) and the dashboard stats
- **Per-record style provenance** (`generation.include_style_metrics`, off by default) — when on, each output record's metadata gains a flat `style_*` block: the per-assistant-turn measurements aggregated into means (the arm-table analogue), flattened with a `style_` prefix so the schema-stable "flat dict of scalars, same keys/types on every record, −1.0 gaps" contract holds unchanged. Grounding without context stays a −1.0 gap, `style_turns` records the row count, and duplication rows measure only the turn they carry. Making the dataset self-describing about its own style is the point of the scotoma measurement family
- **Metadata schema v5 → v6** — adds `quality_tic_density` (−1.0 gap when the toggle is off or unscored, exactly like the roleplay columns) and the optional `style_*` block; `tests/test_opening_mode.py` asserts the new keys and version
- **Configuration Editor** — two new checkboxes: **Include Style Metrics in Metadata** (Generation section) and **Tic density** (Quality Scoring section), wired through save/load like their neighbours
- **What was deliberately NOT ported from scotoma** — the spaCy-dependent parsers, the judge-server scorers (`basket_score`, `detect_tics`, `struct_census`), the offline span markers (`mark_*`, `mine_frames`), the capability probe (`lexical_probe`) and the embedding clusterer (`closer_concentration`): they either need dependencies this project doesn't take or duplicate machinery the generator already has (its own judge, its own rewrite loop). See plan.md §2 for the full triage

### v11.6.2
- **Configuration Editor text no longer collapses into a vertical column** — some explanatory captions in the editor were rendering one character per line, producing a tall, unreadable sliver of text. The worst cases were the description directly beneath **Rewrite rounds per reply** on the Detection tab and the **Logit Bias** block on the Samplers tab. The cause was a wrapping loop: a label was being wrapped against a container that was itself sized by that label, so each pass made the text narrower until it was a single character wide. Labels now wrap against a container with a real, allocated width, and every affected caption across all tabs (including the long **Enable Bad Words** description) reads as normal prose at every supported window size, down to the 760×520 minimum
- **Spinbox number fields are readable again** — the **Rewrite rounds per reply (1-5)** box on the Detection tab appeared as a solid white box with no visible number and could not be typed into. The dark theme sets spinbox text to white but never sets the field background, so the field fell back to the platform's native white: white text on white. Both spinboxes in the editor (the rewrite rounds box and **Persona Breakthrough Turn**) now share a single `Readable.TSpinbox` style that pins the field to the theme's own entry colours, keeps the digits legible while the box is disabled, and falls back to a known-good colour pair if a theme reports an unusable combination. The rounds box is also fully usable once Regex Watch is enabled
- **New regression test** — `tests/test_editor_readability_ui.py` builds the real Configuration Editor under the production theme and asserts that no label collapses to a column and that every spinbox keeps readable contrast, including its disabled state. It runs under `xvfb-run` and skips cleanly without a display

### v11.6.1
- **Regex Watch tab readability fix** — the **🔎 Regex Watch** dashboard tab rendered its two tables with the theme's default `Treeview` metrics, which pack a 10pt font (17px linespace) into a flat 20px row. Every row had 3px of slack, so cell text was clipped top and bottom and the whole tab read as scrunched, overlapping text. Both tables now use a dedicated `RegexWatch.Treeview` style with an explicit font and a row height measured from that font's linespace plus padding (the same fix the Review and Queue tables already carry), and their columns are sized from the heading text so no header is truncated. The row height is stable at every supported window size

### v11.6
- **Regex Watch** — a new detection area for rhetorical *shapes* rather than fixed phrases (`"it is not just X, it is Y"`, `"more than just a Z"`, `"less about X and more about Y"`). Patterns are regular expressions, shipped with six defaults and fully editable
- **Rewritten by the main API, not a fixer slot** — a hit is sent back to the same main API slot that produced the text, so the model rewrites in its own voice. There is no fixer slot and no fixes list: the instruction is built from the pattern and the text it matched
- **Bounded and validated** — up to `detection.regex_watch.max_rounds` rewrites per reply (default 3), each followed by a re-check of the whole reply, so a rewrite that introduces a second forbidden shape is caught in the same pass. A rewrite that is empty, too short, still matches its own pattern, or unbalances quotes is discarded and the original kept
- **End-user curated** — add, edit, remove, test and restore patterns in the Configuration Editor's Detection tab. An uncompilable pattern is refused at save time; one already in `config.yml` is logged and skipped rather than silently disabling the pass
- **Dashboard area** — a new **🔎 Regex Watch** tab lists every configured pattern with its hit count and last status, plus the recent hits and the rewrite outcome (`rewritten` / `unresolved`). Hits also feed the Regex Watch metric card and the issue graph

### v11.5
- **Judge JSON Is Recovered Instead of Dropped** — Small local judges (Qwen 3.5 4B and similar) used to lose roughly one conversation in five to malformed JSON. A reply is now parsed through a ladder: direct parse → balanced-object scan (survives thinking blocks, prose and ``` fences anywhere) → structural repair (trailing commas, unescaped quotes, cut-off tails) → lenient normalisation (smart quotes, Python literals) → numeric salvage. A candidate object that actually carries the score keys wins over an unrelated `{...}` in the prose
- **Format-Repair Round** — if nothing parses, the model's own broken reply is sent back and it is asked for the same evaluation as JSON only (`quality.judge_json_repair_attempts`, default 1, `0` = v11.4 behaviour). Only a reply that still fails is an `invalid_json` drop
- **Truncation Is Transient, Not Fatal** — a reply cut off by the token limit (`finish_reason: length`) is salvaged when the scores were already written, otherwise retried with a doubled token budget (`quality.judge_max_tokens`, 0 = automatic). This was the actual cause of most "Unterminated string" errors
- **Optional Structured Output** — `quality.judge_structured_output` (`auto` by default) sends `response_format: {"type": "json_object"}`; an endpoint that rejects it is retried once without the field and remembered for the rest of the run (`json_schema` builds a real schema from the active dimensions, `off` keeps v11.4 payloads)
- **Judge Replies Are Logged** — the raw reply, its `finish_reason` and how the JSON was recovered now go to the per-slot debug log, so a remaining failure is diagnosable instead of a one-line warning
- **Smaller Fixes** — score values like `"85"`, `"85/100"` or `about 72` are coerced instead of defaulting to 50; an unreadable response envelope and an empty reply are transient failures (retried) rather than `invalid_json`; per-slot judge latency bookkeeping no longer slices the wrong list

### v11.4
- **Quality Judge Retries, Then Drops** — The quality judge now retries a transient failure (network error, timeout, non-200 status, unreadable response) up to 3 times, with a configurable back-off (`quality.judge_max_attempts`, `quality.judge_retry_delay`). If every attempt fails, the conversation is **dropped**: it is not written to the dataset, not stored as a score and not flagged for review
- **Invalid JSON and Logic 0 Drop Immediately** — A judge reply that is not valid JSON, or a conversation-level `logic` score of 0, drops the conversation on the spot with no retry. There is no heuristic fallback for a failed judge any more: an unjudged conversation can no longer slip into the dataset
- **Review Tab Rebuilt** — Flagged conversations are now selectable with a single click, the table has readable row heights and stretches its columns, the detail pane shows the real transcript (read back from the output files or the database) and scrolls on its own, the selection survives dashboard refresh ticks, and **Export Flagged → JSONL** actually writes `output/quality_review_flagged.jsonl` (main output, per-API duplication files and database rows)
