# 📝 Version History

The changelog is split by major series so the current release notes stay short.

| Series | Covers |
|--------|--------|
| [v13.x](changelog-v13.md) | Headless / CLI control: a GUI-free `run_config` + `control` + `cli` layer so the generator can be launched, driven, inspected, exported and shut down from a terminal (by a human or an LLM) against the existing `config/config.yml`, with a JSON statistics payload covering both meanings of "filtering" (v13.0), plus the v13.0.1 fix for a `shutdown` that reported success while leaving the controller process spinning, and the v13.0.2 fix for a `Start processing:` line that announced the legacy `api.threads` scalar instead of the number of threads actually launched, the v13.0.3 fix for an async-scoring write that skipped `app_state.output_data_lock`, and the v13.0.4 fix for the Slop Fixer, Anti-Slop Fixer and Quality Judge never sending `chat_template_kwargs` (so a reasoning model thought on every rewrite and score request regardless of the Samplers-tab Thinking Mode) plus the per-request `enable_thinking` overrides, and the v13.0.5 fix for progress accounting under `quality.async_scoring` (the worker refunded every async-scored task's turns, so a completed task contributed zero and the bar stalled and oscillated around 60 turns), and the v13.1.0 **📊 Metrics** dashboard tab, which reads vLLM's own `/metrics` endpoint and shows prompt-processing speed, token-generation speed and endpoint load **per API endpoint, never aggregated**, plus a per-endpoint graph, and the v13.1.1 fix for the state save that made a long run slow down in bursts (the whole state document was re-serialised synchronously on every completed task, from every worker and every judge thread, on one global lock — 0.19 s per save at 500 tasks, 4.3 s at 12,000) plus the opt-in `generation.debug_prompt_log` for the per-request prompt traces, and the v13.2.0 `{style}` variable, named by every shipped prompt and filled from a run-wide deck dealt WITHOUT replacement so about 18% of rows no longer share their first three or four words, and the v13.2.1 fixes for the `UnboundLocalError` that made **every task fail on a config with no datasets**, the `{style}` instruction that leaked into 25% of saved messages as a stage direction above the prose, and the scene-cast schedule that put an arrival on the final reply and dropped a 3-character scene below `min_present`, and the v13.3.0 optional 📊 Metrics columns for the antislop-vllm-fork proxy's own counters (opt-in via `metrics.antislop_columns`, with a fork whose upstream vLLM is down now counting as reachable rather than `unreachable`), and the v13.4.0 **overhaul of the 📊 Metrics tab** — a four-card KPI strip, three more graph panels (per-slot achieved throughput, proxy request/ban/back-track rates, and running-vs-waiting queue depth), the proxy's full twelve-metric set instead of four, wide grabbable scrollbars on the 22-column table, and the proxy columns showing themselves when a slot actually serves them , and the v13.5.0 fix for a 📊 Metrics tab that was slow and unreliable — the poller ran every 10 s and fetched endpoints serially, so one dead host delayed every other sample and a burst of activity landed as a single spike; it now polls every 2 s **concurrently**, keeps 300 samples instead of 120, and **saves the history to `output/metrics_history.json` by default** so the figures survive the window closing, and the v13.5.1 fixes for the scene-cast feature that made a multi-character scene read as one voice with three names — the `SCENE CAST` note that leaked into saved messages as a stale header above the prose, the man's opening message that was generated with no cast note at all (so he wrote every character as present and the first answer then had to narrate an arrival for someone he was already touching), his later messages that never saw the cast note (so he could address a character who had left), the `{style}` opener that was applied to every assistant reply instead of only the first, the exit beat that was identical in every row because the guidance was indexed by slot number alone, and the headless controller crash on a refusal-phrase hit (the `detection` issue-timestamp globals were wired up only by the GUI entry point) (**current: v13.5.1**) |
| [v12.x](changelog-v12.md) | The README split into per-topic pages, Scene Cast and scene continuity, the `cast_continuity` judge dimension, metadata schema v7, the duplicated-turn / repeated-opener / repeated-reply guards, the always-on repeated-word collapse, and the v12.7.6 slop/anti-slop default-off change that steers users to AntiSlop-vLLM's dev branch, the v12.8.0 optional cleaner pipeline, the v12.8.1 random-names deck, the v12.8.2 **Drop Selected** action in the Review tab, and the v12.8.3 first-reply opener caps plus the fix that had both repeat guards silently off in single-API mode, and the v12.9 configurable judge concurrency, judge rate-limit slot and async judge queue, the v12.9.1 fix for the `NameError` that made async scoring crash on Start, and the v12.9.2 fix for the per-turn logic gate freezing generation behind the judge |
