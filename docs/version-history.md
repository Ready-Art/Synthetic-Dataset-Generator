# 📝 Version History

The changelog is split by major series so the current release notes stay short.

| Series | Covers |
|--------|--------|
| [v14.x](changelog-v14.md) | The v14.3.0 fixes for **the scene-continuity check that fired on the reply it asked for** — a character scheduled to arrive on slot N is still `absent` when slot N's note is built, so `_cast_names_for_slot()` put it in the **blocked** list AND the **expected** list on the same slot: the note said `Dani ARRIVES in this reply` and the check then flagged the model for writing exactly that, regenerating every arrival reply to exhaustion (`Scene continuity violation ... fixes exhausted`), plus `find_character_actions()` blaming a name that is the **object of a preposition** (`She looks at Dani and smiles` — the largest source of false `exited_acts` hits on real prose), and the change that makes an unfixable continuity miss **DROP the conversation** instead of keeping its best-effort text (a cast contradiction makes the row argue with itself, unlike a style miss), recorded as `scene_continuity` in `app_state.quality_dropped` and still credited for progress; the v14.2.2 fixes for **Scene Cast in a 2-character scene** — the leave budget was computed against the *leavable* set (`len(leavable) - 1`) instead of `spare`, so with one leavable character the budget was 0 and a configured `exit_slot` was never scheduled at all (the character simply never left); the `ARRIVES` directive was never emitted, because a character scheduled to arrive on slot N is still `absent` when slot N's note is built and the transition scan skipped every non-`present` state (so newcomers appeared late and unprompted, often only after the user called them over); the note contradicted itself on an arrival slot by listing the newcomer under both `NOT IN THE SCENE` and `ARRIVES` (a model handed a contradiction does neither); and the simulated user's presence-only note listed a mid-arrival character as `PRESENT`, so he wrote *"Come here, Teresa"* one reply before she was written entering the room and the next reply then narrated her walking in from outside — the v14.2.1 fix for the **Review tab that counted but listed nothing** — the tab's own count badge rewrote its label to `"Review (5)"`, and every per-tick refresher gates on the visible tab matching a `ui_theme.TAB_*` constant, so the raw-label comparison stopped matching the moment the badge appeared and the table silently stopped rebuilding (Export still wrote all five rows, because it reads the flagged-id set rather than the table); the badge is now built by `ui_theme.tab_badge()` and every label comparison goes through `ui_theme.tab_base_name()`, and the flags themselves are now persisted in the state file (they were only ever held in memory, so a resumed run restored every score and showed an empty Review tab) with `generation._derive_review_ids()` covering a pre-existing state file; the v14.2.0 fix for **one TCP connection per request** — every call site used the module-level `requests.post(...)` helper, which builds a throwaway `Session` per call, so a 40-thread run against a local vLLM behind nginx opened thousands of connections a minute and filled the server's socket table with `ESTAB` entries against `:443` (it was never extra requests, it was the same requests each paying for a new connection); `api_handler.py` now owns one shared pooled `requests.Session` behind an `HttpClient` facade that `generation`, `quality` and `vllm_metrics` all bind their `requests` name to, so all ~100 call sites are unchanged, with connect-only retries (a read timeout is never silently resent, which would duplicate generation work) and transparent re-open of connections nginx has closed while idle — measured 120 requests / 8 threads going from 120 connections and 1.04 s to 8 connections and 0.67 s; the v14.1.0 fix for **characters who never left the scene** — the state machine decided a scheduled exit had landed by searching the reply for the character's *name*, so `"Cole is still here"` exited him while `"She grabbed her coat and left"` cancelled the exit, and the new `exit_detection` / `join_slot` / `exit_slot` keys with their Scene Cast panel controls; and the GUI rebuilt on a design system: one new `ui_theme.py` token module owning every colour, font, spacing value and tab name (0 hex literals outside it, down from 278), fonts resolved from a stack so the layout is the same on Windows, Linux and macOS, the `MetricValue.TLabel` style that was referenced but never defined (so the Overview numbers rendered at caption size), a hand-built button hierarchy because every ttkbootstrap variant resolves to one identical colour pair on both themes, the switch to the `one-dark` theme with every surface literal replaced in the same pass, a visible scrollbar thumb (it was drawn in exactly the colour of its trough), focus and hover states for the 47 bare buttons and for check/radio buttons (whose `map()` was empty), ASCII fallbacks for ~130 emoji when no colour-emoji font is installed, empty states for every table, and the tab strip consolidated 12 → 8 losslessly (`Totals` into `Overview`, `API 1`..`API 4` into one `APIs` tab) with the action bar moved into the header (**current: v14.2.2**) |
| [v13.x](changelog-v13.md) | Headless / CLI control: a GUI-free `run_config` + `control` + `cli` layer so the generator can be launched, driven, inspected, exported and shut down from a terminal (by a human or an LLM) against the existing `config/config.yml`, with a JSON statistics payload covering both meanings of "filtering" (v13.0), plus the v13.0.1 fix for a `shutdown` that reported success while leaving the controller process spinning, and the v13.0.2 fix for a `Start processing:` line that announced the legacy `api.threads` scalar instead of the number of threads actually launched, the v13.0.3 fix for an async-scoring write that skipped `app_state.output_data_lock`, and the v13.0.4 fix for the Slop Fixer, Anti-Slop Fixer and Quality Judge never sending `chat_template_kwargs` (so a reasoning model thought on every rewrite and score request regardless of the Samplers-tab Thinking Mode) plus the per-request `enable_thinking` overrides, and the v13.0.5 fix for progress accounting under `quality.async_scoring` (the worker refunded every async-scored task's turns, so a completed task contributed zero and the bar stalled and oscillated around 60 turns), and the v13.1.0 **📊 Metrics** dashboard tab, which reads vLLM's own `/metrics` endpoint and shows prompt-processing speed, token-generation speed and endpoint load **per API endpoint, never aggregated**, plus a per-endpoint graph, and the v13.1.1 fix for the state save that made a long run slow down in bursts (the whole state document was re-serialised synchronously on every completed task, from every worker and every judge thread, on one global lock — 0.19 s per save at 500 tasks, 4.3 s at 12,000) plus the opt-in `generation.debug_prompt_log` for the per-request prompt traces, and the v13.2.0 `{style}` variable, named by every shipped prompt and filled from a run-wide deck dealt WITHOUT replacement so about 18% of rows no longer share their first three or four words, and the v13.2.1 fixes for the `UnboundLocalError` that made **every task fail on a config with no datasets**, the `{style}` instruction that leaked into 25% of saved messages as a stage direction above the prose, and the scene-cast schedule that put an arrival on the final reply and dropped a 3-character scene below `min_present`, and the v13.3.0 optional 📊 Metrics columns for the antislop-vllm-fork proxy's own counters (opt-in via `metrics.antislop_columns`, with a fork whose upstream vLLM is down now counting as reachable rather than `unreachable`), and the v13.4.0 **overhaul of the 📊 Metrics tab** — a four-card KPI strip, three more graph panels (per-slot achieved throughput, proxy request/ban/back-track rates, and running-vs-waiting queue depth), the proxy's full twelve-metric set instead of four, wide grabbable scrollbars on the 22-column table, and the proxy columns showing themselves when a slot actually serves them , and the v13.5.0 fix for a 📊 Metrics tab that was slow and unreliable — the poller ran every 10 s and fetched endpoints serially, so one dead host delayed every other sample and a burst of activity landed as a single spike; it now polls every 2 s **concurrently**, keeps 300 samples instead of 120, and **saves the history to `output/metrics_history.json` by default** so the figures survive the window closing, and the v13.5.1 fixes for the scene-cast feature that made a multi-character scene read as one voice with three names — the `SCENE CAST` note that leaked into saved messages as a stale header above the prose, the man's opening message that was generated with no cast note at all (so he wrote every character as present and the first answer then had to narrate an arrival for someone he was already touching), his later messages that never saw the cast note (so he could address a character who had left), the `{style}` opener that was applied to every assistant reply instead of only the first, the exit beat that was identical in every row because the guidance was indexed by slot number alone, and the headless controller crash on a refusal-phrase hit (the `detection` issue-timestamp globals were wired up only by the GUI entry point), and the v13.5.2 fixes for the exit beat that was narrated twice (the man's message and the assistant's reply both performed the same departure, because the cast note handed to the man carried the `LEAVES`/`ARRIVES` directive that only the assistant should act on) plus the new opt-in `detection.foreign_word` check for a word from another language written in Latin letters ("green olhos", "brown ojos") or two words fused with a capital in the middle ("visiblyTrembling"), which the script-based non-Latin check cannot see (**current: v13.5.2**) |
