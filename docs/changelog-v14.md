# 📝 Changelog — v14.x

Newest first. [v13](changelog-v13.md) holds the rest of the history.

### v14.0.0
- **The GUI was rebuilt on a design system.** The window looked old and clunky, and it was not one bug — it was the absence of a design system. Every colour, font, spacing value and tab name now lives in one new module, `ui_theme.py`, and every widget style is built from those tokens by a named `configure_*_styles()` function. Nothing about what is sent to an API, written to an output file or defaulted in `config/config.yml` changed: a default run is byte-identical
- **New: `ui_theme.py`** — a token module holding the palette, the font stacks, the size and spacing scales, the window geometry, the tab names and the style builders. It is **pure data plus pure helpers**: importing it never creates a Tk object, so it is safe from a headless test, the CLI and the layout harness. `grep -c "#[0-9a-fA-F]\{6\}" *.py` is now **0** outside that file, down from 278 hand-picked hex literals scattered across `generate.py`, `dashboard.py` and `config_editor.py`
- **Fixed: the theme's surfaces never lined up** — the app ran the `superhero` theme (a dark `#2b3e50` frame) while the hand-written panel colours were a *different, bluer* dark (`#2a2a35`, `#1e1e24`, `#16161c`), so every table and issue panel sat on a slightly wrong background. The theme is now **`one-dark`** and the same pass replaced every literal, so the surfaces actually agree. The theme is a **code constant**, not a config key, because a config switch would let a default run differ from the previous release
- **Fixed: the app looked different on every OS** — everything asked for `Segoe UI` and `Consolas`, which exist only on Windows. Tk silently substitutes a different family with different metrics elsewhere, so the layout that was tuned on Windows was not the layout anyone else saw. All 45 hard-coded font tuples now go through `ui_theme.resolve_font()`, which walks a font **stack** and returns the first family Tk actually has
- **Fixed: the metric cards were sixteen identical text blobs** — `_create_ttkbs_metric()` put the big number in `style='MetricValue.TLabel'`, a style that was **never defined anywhere**, so `style.lookup('MetricValue.TLabel', 'font')` returned empty and the headline number rendered at the same 10pt as its caption. `MetricValue.TLabel` is now defined at 22pt bold, and the Overview reads as actual cards
- **Fixed: the Start button had no visual weight** — under both themes, `TButton` and every ttkbootstrap variant (`Accent`, `primary`, `success`, `danger`, `secondary`, `info`, `warning`, `outline-primary`) resolved to **one identical colour pair**, so the primary action was indistinguishable. The button hierarchy is now hand-built with explicit `configure()` + `map()` calls — `Primary`, `Secondary`, `Ghost` and `Danger` — and Start is the only `Primary`. The primary fill is `#3a63c0`, not the theme's own `primary #6693f5`, which is only **2.98:1** behind white text and fails WCAG AA; `#3a63c0` measures 5.64:1
- **Fixed: the scrollbar thumb was invisible** — on `one-dark` the scrollbar's `background` and `troughcolor` were both `#282c34`, so the thumb was drawn in exactly the colour of the trough behind it. The thumb is painted from `darkcolor`/`lightcolor` on the `Vertical.TScrollbar.thumb` element, not from `background`, so both are now set, the trough is `#21252b`, and the width is 12px instead of 8px
- **Fixed: keyboard focus was invisible on 47 buttons** — the bare `TButton` style had no `focus` entry in its `map()` and a `focuscolor` of `#ffffff`, i.e. white on a near-white button face. It now has a `focus` entry pointing at the accent. `TCheckbutton` and `TRadiobutton` had a **completely empty `map()`** and no `indicatorcolor` at all, so they gave no feedback on hover, focus or press; they now do
- **Fixed: emoji rendered as tofu boxes** — ~130 emoji acted as icons in buttons, tabs and card titles, and render as empty rectangles wherever no colour-emoji font is installed, which is most bare Linux boxes. `ui_theme.icon_text()` and `icon()` now check once at startup whether the family resolves and fall back to a plain ASCII marker (`[>] Start Generation`, `[!] Errors`, `[DB] Database & Cache Status`) when it does not. Where the font **is** present the text is returned unchanged, so Windows appearance is untouched
- **New: empty states** — a `Treeview` with no rows was a blank rectangle that read as a rendering failure rather than as "nothing has happened yet". `ui_layout.empty_state()` now inserts one muted placeholder row into the Regex Watch hits table, the three Queue tables and the Quality scores table
- **The tab strip is consolidated 12 → 8, losslessly** — `Totals` folds into `Overview` and `API 1`..`API 4` become one `APIs` tab with a slot selector. Every panel, table and graph survives; the rest is a rename. `Overview, APIs, Quality, Review, Regex Watch, Metrics, Prompts, Queue`. The emoji prefixes are gone from the tab names, which also fixes `🔍` meaning both Review and Prompt Viewer. The tab names are now constants in `ui_theme.py` — the codebase had five separate hard-coded copies of `"🔍 Review"`
- **The action bar moved into the header** — Start/Pause/Stop sat in the middle of the window, above the notebook. They are now in the header row next to the version label, and the root rows are header / notebook / status bar
- **Overview puts the watched content first** — the run controls and progress bars are at the top, then the metric cards, then the issue panels and the 60-minute graph; the database status, API response times and Tools buttons are folded into one collapsed **Diagnostics** section, because they are only interesting when something looks wrong
- **Version bumped to v14.0.0** — a **major** bump: the front end is a new design system, the theme changed, the tab strip was consolidated and the release notes file is new. No config key was added, removed or redefaulted, so a default run is byte-identical to v13.5.2
