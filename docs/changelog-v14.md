# 📝 Changelog — v14.x

Newest first. [v13](changelog-v13.md) holds the rest of the history.

### v14.2.2
- **Fixed: a character never left the scene in a 2-character run, whatever `exit_slot` said.** The leave budget was `min(max_leaves, spare, max(0, len(leavable) - 1))`. The `- 1` was meant to keep at least one character in the room, but it counted the **leavable** set rather than the **present** set — and a scheduled joiner is not in `leavable` at all. So in the common 2-character scene with `min_present: 1` (spare = 1) the single leavable character gave `len(leavable) - 1 == 0`, and the departure was **silently dropped**. `exit_slot` was configured, clamped, honoured by every later guard — and never used, because nothing was ever scheduled to leave. The budget is now `spare` (`cast_size - min_present`), which is the correct number: every transition in flight costs exactly one present character. The existing block that pushes an exit past a pending arrival still keeps the two from overlapping, so `min_present` holds at every reply (verified across 4,608 character/slot/`min_present`/shape/slot-override combinations, 0 violations)
- **Fixed: the `ARRIVES` directive was never emitted at all.** A character scheduled to arrive on slot N is still `absent` when slot N's note is built — the state only flips to `arriving` when `_advance_cast_state()` runs, *after* the reply comes back. `_cast_slot_transitions()` skipped every state that was not `present`, so it skipped exactly the slot the directive was meant for. The model was told who was **not** in the room and never told to bring them in, which is why newcomers appeared late, unprompted, and often only after the user had called them over. `absent` is now treated as a live state: a member whose `enter_slot` is this slot is reported as arriving
- **Fixed: the cast note contradicted itself on an arrival slot.** It said `NOT IN THE SCENE: Ines.` and `Ines ARRIVES in this reply.` in the same note. A model handed a contradiction resolves it by doing neither. The arriving character is now listed on its own `ARRIVING IN THIS REPLY:` line and is never also listed as absent
- **Fixed: the simulated user summoned a character who had not arrived yet.** The man's presence-only note (`transitions=False`) listed a mid-arrival character as `PRESENT`, so he wrote *"Come here, Teresa"* one reply before she was written entering the room — and the next reply then narrated her walking in from outside, as if she had heard him through a wall. For the man a mid-arrival character has **not arrived yet**, so she is now `NOT IN THE SCENE`, and his note carries one extra line forbidding him to speak to, call out to, summon or wait for an answer from an absent character. An `exiting` character stays `PRESENT` for both readers, because the exit has not been narrated yet
- **No config key and no change to what is sent or written on a default run.** Scene Cast still ships `enabled: false`, so a default run is byte-identical to v14.2.1. The three fixes only change the plan and the notes when the feature is on
- **Version bumped to v14.2.2** — a **patch** bump: three correctness fixes inside an existing opt-in feature, with no new config key and no new GUI control

### v14.2.1
- **Fixed: the Review tab showed a count and an empty list.** The tab label carries a live badge (`"Review"` at zero, `"Review (5)"` once five conversations are flagged), and every per-tick refresher is gated on the *visible* tab matching a `ui_theme.TAB_*` constant. That comparison used the **raw label**, so the moment the badge appeared the Review table decided it was not on screen and stopped rebuilding. The result was exactly what you saw: the tab said `Review (1)` (or `(5)`), the list below it was empty, and **Export Flagged → JSONL still wrote all five rows** — because Export reads the flagged-id set directly instead of the table. Nothing was ever lost; the list simply stopped being drawn. The badge is now built by `ui_theme.tab_badge()` and every label comparison goes through `ui_theme.tab_base_name()`, so a badged tab still matches its constant. Four sites needed it: `generate._active_dashboard_tab_text()`, `dashboard._active_dashboard_tab_text()` (the issue panels and the graph), the tab-strip reorder loop, and the badge writer itself — which also froze at its last value, since it looked its own tab up by the label it had just changed
- **Fixed: the Review flags were lost on resume.** `quality_scores` was written to the state file but `quality_review_ids` was not, so resuming a run restored every score while the Review tab came back empty — the flagged rows were still in the dataset and still below the threshold, and Export found nothing to write. The flags are now persisted (snapshotted under `quality_review_lock`, since a judge thread mutating the set mid-iteration raises `RuntimeError: Set changed size during iteration`) and restored by both loaders. A state file written before this release has no such key, so both fall back to `generation._derive_review_ids()`, which applies the same rule the scoring path does: below `quality.min_score_threshold` and not dropped
- **No config key, no change to what is sent or written.** The dataset, the requests and every default are untouched; only the Review tab's own display and the state file's contents changed
- **Version bumped to v14.2.1** — a **patch** bump: a display and state-persistence fix with no new config key

### v14.2.0
- **Fixed: the generator opened a new TCP connection for every single request.** Every call site used the module-level `requests.post(...)` helper, which builds a **throwaway `Session` for that one call**: a fresh TCP connection, a fresh TLS handshake, one request, then close. From every generation thread and every judge thread. Against a local vLLM behind nginx that is one connection per request, thousands per minute, and the server's socket table fills with `ESTAB` entries against `:443` — which reads as the client spamming connections. **It was never extra requests.** It was the same requests each paying for a new connection, and the handshake cost was paid on every one of them. Measured against a keep-alive server, 120 requests across 8 threads: **120 connections and 1.04 s before, 8 connections and 0.67 s after**
- **New: one shared, pooled HTTP session** — `api_handler.py` now owns a single `requests.Session` with a mounted `HTTPAdapter` (pool size 64, so a 40-thread run holds ~40 sockets steady instead of opening thousands). It is exposed as the `HttpClient` facade `api_handler.http`, and `generation`, `quality` and `vllm_metrics` each bind their module-level `requests` name to that one object, so **all ~100 call sites are unchanged** and `requests.exceptions.Timeout` still works. The `/metrics` poller shares it too — it runs every 2 s against every endpoint, so it was a steady drip of fresh connections on top of the workers'
- **Retries are connect-only, deliberately.** A failed *connection* is retried twice; a **read timeout is not retried at all**, because on a generation request the model may already have produced tokens and resending it would silently duplicate work and bill the slot twice. A read timeout still fails the request and goes through the normal retry/fix ladder. (`allowed_methods=None` is required for the connect case, since urllib3 otherwise refuses to retry POST.)
- **A reused connection that the server has closed is handled, not a regression.** nginx closes idle keep-alive connections after `keepalive_timeout` (75 s by default) and the rate limiter can park a slot for up to 60 s, so a pooled connection can be dead when it is next used. urllib3 2.x detects that and re-opens transparently — verified at 0/6 failures across idle gaps longer than the server's timeout — so **you do not need to raise `keepalive_timeout`**
- **No config key and no behaviour change on the wire.** The request bodies, headers, timeouts, rate limiting, circuit breaker and the thinking-mode rules are all untouched: only the connection underneath them is reused. A default run sends byte-identical requests to v14.1.0. Behaviour on the server side is unchanged apart from far fewer connections
- **Version bumped to v14.2.0** — a **minor** bump: a transport-layer change with no config key, no new GUI control and no change to what is sent or written

### v14.1.0
- **Fixed: characters never left the scene.** This was the whole feature appearing not to work, and it was not the schedule — it was how the generator decided a scheduled exit had *landed*. `_advance_cast_state()` searched the reply for the character's **name anywhere**, which was wrong in both directions. `"Cole is still here, arguing"` contains `Cole`, so the exit was recorded as landed and the **next** reply then blocked a character who had never left the room — the generator itself made the transcript incoherent, which is the exact failure Scene Cast exists to prevent. And `"She grabbed her coat and headed for the door"` contains no name at all, because prose uses pronouns, so a perfectly good exit was recorded as `exit_deferred` and then `exit_cancelled`. **That second half was the common case, not the edge case**, which is why characters seemed to stay forever no matter how many replies the conversation had
- **New: transition detection reads the reply for a departure, not for a name.** `detection.find_transition_evidence()` looks for a departure/arrival **verb** in a sentence that is *about* the character — the name in the same sentence, or a **pronoun when exactly one character is mid-transition** (with two candidates a pronoun would be a guess, so it is ignored). A negated sentence is never evidence, so `"Cole did not leave"` and `"Cole stayed put"` do not land an exit. When two characters share a sentence the one closest to the verb owns it, so `"Cole watched Ines leave"` exits Ines, not Cole. Attributed dialogue counts (`"I have to go," Cole said`), because that is a departure the reader sees
- **New config key `prompts.scene_cast.exit_detection`** — `evidence` (default, the behaviour above), `name` (the old v12.0 name-anywhere test, kept so the change can be A/B'd without editing code) or `always` (every scheduled transition lands whether the reply narrates it or not — use with care, it can mark a character gone who is still visibly in the room). An unrecognised value falls back to `evidence`. Ships `evidence`
- **New config keys `prompts.scene_cast.join_slot` / `exit_slot`** — place the beats by reply number, `0` = automatic. The automatic anchors put the arrival at the first third and the departure at the halfway point, which suits a long conversation but not a short one: with 4 replies the exit landed on reply 3, so the scene ended before the departure had an aftermath and it read as no departure at all. Both are **clamped, never trusted** — an arrival is pulled into range and cannot be the opening reply, a departure always keeps a reply after it, and an exit is never scheduled on or before the arrival it follows. Both ship `0`
- **New: three controls in the Scene Cast panel** (Character Engine tab) — a **Transition Detection** dropdown, **Join Slot** and **Exit Slot** spinboxes, all saved to and loaded from `config/config.yml` and disabled while the feature is off. A live feasibility readout was also added: it states how many characters `min_present` requires, because the commonest "nothing happens" report is that `min_present` leaves no spare character (2 characters with `min_present: 2` can never change cast at all)
- **Version bumped to v14.1.0** — a **minor** bump: new config keys and new GUI controls, all inert at their defaults. `exit_detection: evidence` is a behaviour change for anyone already running Scene Cast (that is the fix), but the feature still ships `enabled: false`, so a default run is byte-identical to v14.0.0

### v14.0.0
- **The GUI was rebuilt on a design system.** The window looked old and clunky, and it was not one bug — it was the absence of a design system. Every colour, font, spacing value and tab name now lives in one new module, `ui_theme.py`, and every widget style is built from those tokens by a named `configure_*_styles()` function. Nothing about what is sent to an API, written to an output file or defaulted in `config/config.yml` changed: a default run is byte-identical
- **New: `ui_theme.py`** — a token module holding the palette, the font stacks, the size and spacing scales, the window geometry, the tab names and the style builders. It is **pure data plus pure helpers**: importing it never creates a Tk object, so it is safe from a headless test, the CLI and the layout harness. `grep -c "#[0-9a-fA-F]\{6\}" *.py` is now **0** outside that file, down from 278 hand-picked hex literals scattered across `generate.py`, `dashboard.py` and `config_editor.py`
- **Fixed: the theme's surfaces never lined up** — the app ran the `superhero` theme (a dark `#2b3e50` frame) while the hand-written panel colours were a *different, bluer* dark (`#2a2a35`, `#1e1e24`, `#16161c`), so every table and issue panel sat on a slightly wrong background. The theme is now **`one-dark`** and the same pass replaced every literal, so the surfaces actually agree. The theme is a **code constant**, not a config key, because a config switch would let a default run differ from the previous release
- **Fixed: the app looked different on every OS** — everything asked for `Segoe UI` and `Consolas`, which exist only on Windows. Tk silently substitutes a different family with different metrics elsewhere, so the layout that was tuned on Windows was not the layout anyone else saw. All 45 hard-coded font tuples now go through `ui_theme.resolve_font()`, which walks a font **stack** and returns the first family Tk actually has
- **Fixed: the metric cards were sixteen identical text blobs** — `_create_ttkbs_metric()` put the big number in `style='MetricValue.TLabel'`, a style that was **never defined anywhere**, so `style.lookup('MetricValue.TLabel', 'font')` returned empty and the headline number rendered at the same 10pt as its caption. `MetricValue.TLabel` is now defined at 22pt bold, and the Overview reads as actual cards
- **Fixed: the Start button had no visual weight** — under both themes, `TButton` and every ttkbootstrap variant (`Accent`, `primary`, `success`, `danger`, `secondary`, `info`, `warning`, `outline-primary`) resolved to **one identical colour pair**, so the primary action was indistinguishable. The button hierarchy is now hand-built with explicit `configure()` + `map()` calls — `Primary`, `Secondary`, `Ghost` and `Danger` — and Start is the only `Primary`. The primary fill is `#3a63c0`, not the theme's own `primary #6693f5`, which is only **2.98:1** behind white text and fails WCAG AA; `#3a63c0` measures 5.64:1
- **Fixed: the scrollbar thumb was invisible** — on `one-dark` the scrollbar's `background` and `troughcolor` were both `#282c34`, so the thumb was drawn in exactly the colour of the trough behind it. The thumb is painted from `darkcolor`/`lightcolor` on the `Vertical.TScrollbar.thumb` element, not from `background`, so both are now set, the trough is `#21252b`, and the width is 12px instead of 8px
- **Fixed: keyboard focus was invisible on 47 buttons** — the bare `TButton` style had no `focus` entry in its `map()` and a `focuscolor` of `#ffffff`, i.e. white on a near-white button face. It now has a `focus` entry pointing at the accent. `TCheckbutton` and `TRadiobutton` had a **completely empty `map()`** and no `indicatorcolor` at all, so they gave no feedback on hover, focus or press; they now do
- **Fixed: emoji rendered as tofu boxes** — ~130 emoji acted as icons in buttons, tabs and card titles, and render as empty rectangles wherever no colour-emoji font is installed, which is most bare Linux boxes. `ui_theme.icon_text()` and `icon()` now check once at startup whether the family resolves and fall back to a plain ASCII marker (`[>] Start Generation`, `[!] Errors`, `[DB] Database & Cache Status`) when it does not. Where the font **is** present the text is returned unchanged, so Windows appearance is untouched
- **New: empty states** — a `Treeview` with no rows was a blank rectangle that read as a rendering failure rather than as "nothing has happened yet". `ui_layout.empty_state()` now inserts one muted placeholder row into the Regex Watch hits table, the three Queue tables and the Quality scores table
- **The tab strip is consolidated 12 → 8, losslessly** — `Totals` folds into `Overview` and `API 1`..`API 4` become one `APIs` tab with a slot selector. Every panel, table and graph survives; the rest is a rename. `Overview, APIs, Quality, Review, Regex Watch, Metrics, Prompts, Queue`. The emoji prefixes are gone from the tab names, which also fixes `🔍` meaning both Review and Prompt Viewer. The tab names are now constants in `ui_theme.py` — the codebase had five separate hard-coded copies of `"🔍 Review"`
- **The action bar moved into the header** — Start/Pause/Stop sat in the middle of the window, above the notebook. They are now in the header row next to the version label, and the root rows are header / notebook / status bar
- **Overview puts the watched content first** — the run controls and progress bars are at the top, then the metric cards, then the issue panels and the 60-minute graph; the database status, API response times and Tools buttons are folded into one collapsed **Diagnostics** section, because they are only interesting when something looks wrong
- **Version bumped to v14.0.0** — a **major** bump: the front end is a new design system, the theme changed, the tab strip was consolidated and the release notes file is new. No config key was added, removed or redefaulted, so a default run is byte-identical to v13.5.2
