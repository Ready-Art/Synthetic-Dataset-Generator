### `config/config.yml` [1]
**Purpose:** Main configuration file for API settings, generation parameters, prompts, detection, and samplers
**Key:** `api.apis[]`, `generation.*`, `prompts.*`, `detection.*`, `samplers.*`
**Edit for:**
- API endpoints → `api.apis[].url`, `api.apis[].model`, `api.apis[].key`
- Rate limits → `api.apis[].rate_limit_rpm`, `api.apis[].threads`
- Generation settings → `generation.max_character_cards`, `generation.num_turns`, `generation.output_format`
- Prompts → `prompts.system.base`, `prompts.question`, `prompts.answer`, `prompts.greeting`, `prompts.first_line` (variables: `docs/prompts-and-characters.md`)
- Questions-file dataset variables (v11.9.0) → `prompts.questions_dataset.append_alias` (ONE bare alias whose value is appended to every `input/questions.txt` line; `''` = placeholders only, append nothing) and `append_separator` (text between the line and the appended value, real characters, default `"\n\n"`; the Configuration screen stores it escaped — `codec='escape'` in `webapp/config_schema.py` — so a real newline stays visible in a single-line field). A questions-file line is authored text, so it may also contain `{{ds:alias}}` placeholders. Chunk-mode source `.txt` is deliberately NOT rendered: a chunk is cut at a random character offset and could split a placeholder in half
- Opening mode → `prompts.opening_mode`, `prompts.greeting_context`, `prompts.first_line_styles`
- `{style}` (v13.2.0) → `prompts.style.enabled` (ships `true`) and `prompts.style.styles[]` (one beginning instruction per entry; empty falls back to `generation.DEFAULT_STYLE_VARIANTS`). ONE style per conversation, dealt WITHOUT replacement across the run, filled into every prompt that names `{style}`. `enabled: false` sends the pre-v13.2.0 prompts with `{style}` resolving to nothing. **This is the one release that does not keep a default run byte-identical**, because the shipped prompts name the variable and the block ships ON
- Detection phrases → `detection.refusal.phrases`, `detection.slop.phrases`, `detection.user_speaking.*.phrases`, `detection.out_of_character.phrases` (+ `enabled`, `fixes`)
- Slop / Anti-Slop opt-in (v12.7.6) → `detection.slop.enabled` and `detection.anti_slop.enabled`, **both `false` in the shipped config**. These are the only two detection layers whose `enabled` flag is the SOLE gate: `run_config.py` reads the flags into `settings.slop_enabled` / `settings.anti_slop_enabled` and passes an **empty** phrase/fix list to `worker()` when a layer is off, so the worker's existing "no phrases = no detection" path skips it and the detection counters stay at zero instead of counting detections nothing acts on. `slop_to_anti_slop_fallback` is additionally ANDed with both flags, because the fallback needs an anti-slop fixer to fall back TO. **Do not make a layer's phrase list its enable condition** — a saved list has to survive the layer being switched off and on again, and the Configuration screen loads and saves the list unconditionally. The full user-facing rationale (and the twelve reasons to use AntiSlop-vLLM's `dev` branch instead) is `docs/slop-and-antislop.md`; the developer reference is `docs/agents/slop-antislop-default-off.md`
- Non-Latin script check (v11.10.0) → `detection.non_latin.enabled` (off by default) and `detection.non_latin.fixes[]` (one instruction per retry round; empty falls back to `generation.DEFAULT_NON_LATIN_FIX`, so switching the check on needs no fix list). A Unicode range allow-list in `detection.is_non_latin()`: no pattern to compile, no phrase list, no LLM call
- Regex Watch (v11.6) → `detection.regex_watch.enabled` (off by default), `detection.regex_watch.max_rounds` (1-5, default 3), `detection.regex_watch.patterns[]` (regular expressions, user-editable; shipped defaults are mirrored by `detection.DEFAULT_REGEX_WATCH_PATTERNS`). A hit is rewritten by the SAME main API slot, not a fixer slot; there is no fixes list
- Sampler params → `samplers.temperature`, `samplers.top_p`, `samplers.repetition_penalty`
- Bad words (v11.1) → `samplers.use_bad_words` (bool, off by default), `samplers.bad_words` (list of strings; leading whitespace on every entry is preserved exactly as typed, matching vLLM semantics). The single toggle drives every main-API request (question/answer/user-continuation/opening-mode greeting+first-line) plus the Slop Fixer (slot 5) and Anti-Slop Fixer (slot 6), even when those fixers carry their own `slop_fixer_params` / `anti_slop_params` sampler overrides — `generation.apply_bad_words_to_payload()` reads from the TOP-LEVEL `samplers.*` keys so it works regardless of per-slot override state
- Character profiles → `prompts.character.characters[]` (name, race, job, hair, hair_color, clothing, appearance, persona, personality, traits, backstory, setting) — `persona` = inner personality (private self), `personality` = outward behavior (observed manner); `persona` is withheld from the profile and re-injected as a breakthrough block from `prompts.character.persona_breakthrough_turn` onward
- Emotional states/arcs → `prompts.emotional_states.states[]` — each entry is a flat state or a `'->'`-joined progression (`'neutral -> tense -> angry'`) expanded across the conversation's assistant turns
- User-side emotional states/arcs (v10.6.0, optional) → `prompts.user_emotional_states.{enabled,states[]}` — same flat/'->' arc format as `emotional_states` but applied to the SIMULATED USER's messages (generated opening question/first line + each user continuation); off by default; note is ephemeral (user prompt only, never history/system); placement does not apply
- Scene cast / join-leave (v12.0) → `prompts.scene_cast.{enabled,shape,min_present,max_churn,max_deferrals,placement,exit_guidance,arrival_guidance,allow_cutaway,cutaway_note,exit_detection,join_slot,exit_slot}` (off by default; acts ONLY with 2+ selected characters). **The generator owns the cast**: `generation._build_scene_cast_plan()` computes who is present at each assistant slot BEFORE any request is sent, the model is told the state in the per-turn note and only NARRATES the transitions. `shape` is `minimal` (at most one join + one leave), `churn` (up to `max_churn` of each) or `none`. **A join AND a leave each cost one present character**, so 2 characters with `min_present: 2` can never change cast (the worker logs a WARNING and runs a static cast — do not "fix" this into a silent no-op). `placement` is `depth0` (default) or `system`, parsed by `note_placement()` (see `docs/scene-cast.md`). **v13.5.1: `exit_guidance` and `arrival_guidance` ship POPULATED** (8 and 6 entries, deliberately different in kind) and `allow_cutaway` ships `false`. Both matter for variety, not just wording: the guidance is indexed by `(slot_no - 1 + guidance_offset) % len(...)`, and before the offset existed every row of a run picked the SAME entry, because every row has the same `num_turns` and so the exit lands on the same slot number — every row's exit was the same beat. An empty list still falls back to `generation.DEFAULT_EXIT_GUIDANCE` / `DEFAULT_ARRIVAL_GUIDANCE`. `allow_cutaway: true` produced disconnected filler (a reply opening on a stray dog barking, or a stranger asleep in another building) rather than a scene, so it is off by default; the join/leave feature works without it. **v14.1 adds three keys, all inert at their defaults:** `exit_detection` (`evidence` / `name` / `always`, ships `evidence`) decides how a scheduled beat is judged to have LANDED — see `docs/agents/generation.md`, the name-anywhere test was why exits never landed; `join_slot` and `exit_slot` (both ship `0` = automatic) place the beats by reply number and are CLAMPED in `_build_scene_cast_plan()`, never trusted. An unrecognised `exit_detection` falls back to `evidence`
- Scene continuity check (v12.0) → `detection.scene_continuity.{enabled,fixes,max_rounds}` (enabled by default but INERT unless `prompts.scene_cast.enabled` is also on). A character who `exited` or is still `absent` may not speak or act. `detection.check_scene_continuity()` is **code-only** (attributed quoted lines + a curated narration action-verb list; no LLM, no phrase list to sanitize), so an empty `fixes` list falls back to `generation.DEFAULT_SCENE_CONTINUITY_FIX`
- Random names → `prompts.random_names.enabled`, `prompts.random_names.names[]`. Each CONVERSATION gets its own name, dealt by `generation.deal_random_names()` from the configured pool; the character card is never modified, so the name is scoped to that one conversation. The pool is dealt **without replacement** (a shuffled deck in `app_state.random_name_deck`, guarded by `app_state.random_name_lock`, identified by `app_state.random_names_pool_key`), so a long run spreads every configured name instead of redrawing with replacement: the old per-character `random.choice` reached only ~740 of 1,000 names over 1,410 scenes. Dealt names are distinct **within** a scene, and a card's own name is never dealt back (the `avoid` argument). A pool smaller than the scene degrades to its distinct names, never duplicates or blanks. Do NOT go back to a per-character `random.choice` — that reintroduces both the repetition and the same-name-in-one-scene bug. Guarded by `tests/test_random_names.py`
- Conversation history for fixers → `generation.use_conversation_history_for_fixers` (whether to pass conversation context to slop/anti-slop fixer LLMs)
- Output metadata → `generation.include_metadata` (flat, schema-stable provenance block per output.jsonl record; trainer-safe; never modifies `conversations[]`; false = legacy two-field records)
- Repeated opener (v12.5) → `generation.repeat_opener_guard` (off by default; the Configuration screen's label is **"Repeated opener guard"**, from `webapp/config_schema.py`) plus `generation.repeat_opener_fixes` (one per line, cycled; empty = `generation.DEFAULT_REPEAT_OPENER_FIX`) and `generation.repeat_opener_max_retries` (default 1; `webapp/config_schema.py` rejects a negative). A reply whose OPENING content words repeat an earlier one is caught by `detection.is_repeated_opener()` in `generate_answer_with_retries()` (AFTER Regex Watch, LAST before the success return) and resent to the SAME slot. **The instruction goes on the ANSWER PROMPT, never the system prompt**, so the system prompt and history stay byte-identical for a prefix-caching server. Bounded; the best-effort answer is KEPT. No detection timestamp is recorded. This guards the tic `generation.history_size` cannot see: it prunes `app_state.question_history` (recent opening QUESTIONS), never the assistant turns. Worker kwargs `repeat_opener_enabled_local` / `repeat_opener_fixes_local` / `repeat_opener_max_retries`, threaded into `_per_turn_logic_gate`. Guarded by `tests/test_repeat_opener_and_answer_vars.py`
- First-reply opener caps → `generation.first_reply_first_word_cap` / `generation.first_reply_opener_cap` (shares 0-1, 0 = off, both off by default; `webapp/config_schema.py` rejects values outside 0-1) and `generation.first_reply_opener_max_retries` (default 2). Details in [`generation-retries.md`](generation-retries.md); guarded by `tests/test_first_reply_opener.py`
- Repeated reply (v12.7) → `generation.repeat_reply_guard` (off by default; the Configuration screen's label is **"Repeated reply guard"**, from `webapp/config_schema.py`) plus `generation.repeat_reply_fixes` (one per line, cycled; empty = `generation.DEFAULT_REPEAT_REPLY_FIX`) and `generation.repeat_reply_max_retries` (default 1; `webapp/config_schema.py` rejects a negative). The opener guard's SIBLING, for a reply repeated WHOLE rather than just its opener; independent of `repeat_opener_guard`. **The instruction goes on the ANSWER PROMPT, never the system prompt**, the opener guard's prefix-cache contract. Bounded; the best-effort answer is KEPT. No detection timestamp is recorded. Worker kwargs `repeat_reply_enabled_local` / `repeat_reply_fixes_local` / `repeat_reply_max_retries`. Details in [`generation-retries.md`](generation-retries.md); guarded by `tests/test_repeat_opener_and_answer_vars.py`
- Retry missing quotations (v11.7.1) → `generation.retry_missing_quotations` (off by default; the Configuration screen's label is **"Retry missing quotations"**, from `webapp/config_schema.py`). When on, a generated answer whose spoken line has NO quotation marks at all (e.g. `Its funny she says`) is detected by `detection.is_missing_quotation()` inside `generate_answer_with_retries()` (runs AFTER every phrase check + the incomplete-quote check, BEFORE Regex Watch) and sent back to the SAME main API slot for one retry (no fixer slot, nothing appended to the system prompt so prefix caches survive; if it comes back mark-less again the best-effort answer is kept, never dropped). Distinct from `is_incomplete_quote`, which only sees UNBALANCED quotes. Threaded as worker kwarg `retry_missing_quotations_local` (never positional) into `_per_turn_logic_gate` → its rewrite call. Guarded by `tests/test_missing_quotations.py`
- Style metrics (v11.7) → `generation.include_style_metrics` (off by default; when on AND `include_metadata` is on, each record's metadata gains a flat `style_*` block: `style_metrics.aggregate()` over the record's assistant turns, flattened with a `style_` prefix; duplication rows measure only the turn they carry)
- Quality scoring → `quality.enabled`, `quality.use_llm_scoring`, `quality.output_filter`, `quality.roleplay_dimensions` (opt-in roleplay dimensions: voice_distinctiveness / grounding / persona_alignment), `quality.cast_continuity` (v12.0 opt-in `cast_continuity` dimension: **LLM-ONLY, never in HEURISTIC_DIMENSIONS** — there is no measurable proxy for "was that exit earned?", and the objective half of the question is already answered for free by `detection.check_scene_continuity()`; registered in `CAST_LLM_DIMENSIONS` only, and it joins the composite through `active_scoring_dimensions()`), `quality.min_score_threshold`, `quality.max_chars_for_scoring`, `quality.max_profile_chars_for_scoring`, `quality.judge_max_attempts` / `quality.judge_retry_delay` / `quality.result_timeout` (v11.4 judge retry-and-drop policy), `quality.judge_json_repair_attempts` / `quality.judge_max_tokens` / `quality.judge_request_timeout` / `quality.judge_structured_output` (v11.5 judge JSON robustness: format-repair rounds, token budget, request timeout, optional `response_format`), `quality.judge_priority_enabled` / `quality.judge_priority` (v11.8.x vLLM priority scheduling: the toggle decides whether the `priority` field is sent at all — off by default, because backends without priority support reject the unknown field and vLLM rejects a non-zero priority when the served model is not priority-scheduled — and the value is clamped -10..10 with a default of 0, which every vLLM server accepts; -10 is the HIGHEST priority and must stay reachable, never flattened up to 0), `quality.tic_dimension` (v11.7 opt-in heuristic-only `tic_density` dimension, weight 0.10; measured from `style_metrics.py`, off by default like the roleplay dimensions), `quality.scoring_api.{url,model,key}`
- Datasets → `datasets.sources[]` (default `{sources: []}`) — names-only source definitions (kind, location, config/split/revision selectors, imported column names, aliases, visibility). Dataset *records* and credentials are never stored here; see `docs/dataset-bindings.md`

### `config/api_profiles.yml` [2]
**Purpose:** API compatibility profiles for request payload filtering per endpoint
**Key:** Profile definitions with `allow`, `rename`, `detect_hosts`, `label`**Edit for:**
- Add new profile → Add new top-level key with `label`, `allow`, `rename`, `detect_hosts`
- Modify allowed params → Change `allow` list (use `all` or `from_config` for special cases)
- Key renames → `rename` dict (e.g., `repetition_penalty: frequency_penalty`)
- Auto-detection hosts → `detect_hosts` list (exact or `.suffix` for subdomains)
**Profiles:** `openai_compatible`, `openai`, `mistral`, `xai_grok`, `gemini_openai`, `anthropic_openai`, `custom`
