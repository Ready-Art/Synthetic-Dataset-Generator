# 📝 Changelog — v12.x

It is now a **short master README** holding the pitch, a five-step quick start and a documentation map that links every topic page. Nothing was cut: every section moved verbatim into its own file under `docs/`
- **Eighteen topic pages under `docs/`** — `features.md` (15k), `architecture.md` (7.6k, runtime diagram + module table), `installation.md` (1.6k), `configuration.md` (10.5k: datasets, API slots, generation settings), `prompts-and-characters.md` (18k), `detection-and-quality.md` (24k), `samplers-and-infrastructure.md` (6.4k), `usage.md` (12.6k), `output-formats.md` (7.1k), `file-structure.md` (3.8k), `how-it-works.md` (11.5k), `troubleshooting.md` (16k), `performance.md` (4.3k), `key-configuration-details.md` (7.3k), `license-and-credits.md` (2.9k), plus `version-history.md` as an index over `changelog-v12.md` (6.8k) and `changelog-v11.md` (26k)
- **The changelog is split by major series** — the v12 release notes stay short, and the v11-and-earlier history lives in its own file instead of pushing the current notes off the end of the page
- **Headings were demoted one level per file** — a section that was `##` in the monolith is now the page's `#`, and its `###` children are `##`, so each page has a single H1 and a coherent outline. Nothing else in the prose changed
- **Every intra-document anchor was repointed** — a link like `[API Compatibility Profiles](#api-compatibility-profiles)` now names the file that owns the target (e.g. `configuration.md#api-compatibility-profiles`). Checked mechanically: every relative link and every `#fragment` in the new pages resolves
- **Relative links were rebased for `docs/`** — `docs/input-folder.md` became `input-folder.md`, `AGENTS.md` became `../AGENTS.md`, and so on, so the pages render correctly on GitHub from their new location
- **`docs/file-structure.md` and the master README describe the new layout** — the repository tree now lists `README.md` and the `docs/` pages, and the README's documentation map is the entry point a user is expected to follow
- **`AGENTS.md` gained a user-docs rule** — a change now updates the one `docs/` page that owns the feature as well as the matching `docs/agents/` topic file, and `README.md` stays an index (a page past ~25,000 characters gets split along its own headings and added to the map)
- **Version bumped to v12.2** — the title of this README, the GUI version label in `generate.py` and this changelog

The remaining cross-cutting rows (a new detection type, a new quality dimension, scene cast) are listed in every topic file they touch

The old `## Tools` section, which was duplicated at the bottom of the file, is kept once in `tools-and-docs.md`. The `app_state.py` counter/lock/timestamp inventory and the thread-safety pattern moved to `core-modules.md` (the hub points at them)
- **Stale in-file pointers repointed** — "see `generate.py` below", "see Tools" and "where the File Reference below names one" were references to sections that no longer sit below; they now name the topic file that holds the answer
- **`generate.py`'s developer note updated** — the module docstring now lists the topic files and says to read the hub plus one file, instead of telling the agent to reference the monolithic `AGENTS.md`
- **Docs policy** — `AGENTS.md` asks that a change update only the topic file that owns the module, and that any topic file growing past ~12,000 characters be split along module lines rather than appended to. `tools/_split_agents_docs.py` is the one-shot script that produced the split (not part of the test loop, not imported by the app)

### v12.0
- **Scene Cast — characters join and leave a multi-character scene** — the "the world doesn't revolve around the player" feature. The **generator owns the cast**: the schedule is computed before any request is sent, the model is told who is present on each reply, and the model only *narrates* the entrances and exits. It never decides whether a character has left
- **A forgotten exit is cancelled, not assumed** — if the model never writes a scheduled departure, the exit is **cancelled** and the character stays legitimately present. Forcing the exit would make that character's very next legitimate line a continuity violation the generator itself invented. An un-narrated **arrival** is the opposite: it is forced to `present`, because being in the scene is the default and cannot corrupt the transcript. The asymmetry is deliberate
- **Hard continuity check, no LLM** — `detection.check_scene_continuity()` flags a character who has left (or has not arrived yet) speaking or acting: attributed quoted lines (including `Name:` script-style prefixes) plus a curated narration action-verb list. Quoted dialogue is blanked before the action match, so a character merely *mentioned* in someone else's line ("Where is Melody?") never flags. A hit sends the reply back to the same main API slot with a fix; once the fixes are exhausted the best-effort answer is kept, never dropped
- **Cache-safe by construction** — the cast note rides in the per-turn `depth0` note beside the persona/emotion blocks, so the system prompt never changes mid-conversation and a server's prefix cache stays warm. The note itself carries **no per-reply counter**, so two static replies produce byte-identical text
- **Opt-in Judge dimension `cast_continuity`** — the Judge reviews what code cannot: did the entrances and exits read as motivated and natural, and was an exited character brought back? **LLM-only, no heuristic** — there is no measurable proxy for "was that exit earned?", and the objective half of the question is already answered for free by the code check. Off by default
- **Metadata schema v7** — three new flat, type-stable keys on every record: `cast_schedule`, `cast_events` (including `exit_cancelled`, which is how you measure whether the model actually wrote its exits) and `quality_cast_continuity` (`-1.0` when off/unscored)
- **Configuration** — `prompts.scene_cast.{enabled,shape,min_present,max_churn,max_deferrals,placement,allow_cutaway,exit_guidance,arrival_guidance,cutaway_note}` (off by default), `detection.scene_continuity.{enabled,fixes,max_rounds}` and `quality.cast_continuity`. The Config Editor gains a **Scene Cast** panel in the Character Engine tab, a **Scene Continuity Check** panel in the Detection tab and a cast-continuity toggle in Quality Scoring; the main window gains a **Cast Drift** metric card, issue panel and graph series
- **Wiring** — `detection.py` (`check_scene_continuity()`, `find_attributed_speakers()`, `find_character_actions()`), `generation.py` (plan/state helpers, `_cast_presence_note()`, the retry branch, metadata v7, `DEFAULT_SCENE_CONTINUITY_FIX`), `generate.py` (config read + worker kwargs + metric card + issue panel), `config/config.yml`, `config_editor.py`, `app_state.py`, `dashboard.py`, `quality.py`, `docs/scene-cast.md`. Guarded by `tests/test_scene_cast.py`
- **Added `tools/gemma4_thought_fix.py` (NOT application code, and not written by us)** — a standalone axolotl helper for people fine-tuning Gemma 4 26B/31B, **contributed by Karki (a user on Discord)** and redistributed here with a few robustness fixes. Nothing in this application imports, reads or tests it, and no generated output depends on it; it is here only because this tool's datasets are often used to train Gemma 4. See [Gemma 4 Chat Template Fix for axolotl](troubleshooting.md#gemma-4-chat-template-fix-for-axolotl-outside-this-project) and `docs/gemma4-chat-template.md`
