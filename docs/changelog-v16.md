# 📝 Changelog — v16.x

Newest first. [v15](changelog-v15.md) holds the rest of the history.

### v16.1.0
- **The 📊 Metrics tab refreshes itself.** With the page open its figures froze, because the tab only re-fetched on a click while everything it shows is written by another thread: the per-slot throughput ring is appended by the generation threads and the server/proxy rings by the vLLM poller. The tab now polls `/api/metrics` every **2 s** — the same cadence `vllm_metrics.POLL_INTERVAL_SECONDS` reads at, so what you see is what the poller last saw — and an **Auto refresh** switch in the toolbar stops it for a reader who wants the page to hold still. The switch is part of the shared `makeTab` factory, so it is on by default for any polling tab and `unmount()` still clears the interval
- **A polling repaint no longer throws the scroll position away.** `makeTab`'s repaint now runs `dom.captureScroll()` before replacing the screen and `dom.restoreScroll()` after, and the tab body carries a stable `data-scroll-key`. Without that, a tab that repaints every two seconds snapped a scrolled table or graph stack back to the top every two seconds — the same defect the Overview's Recent issues had in v15.1.0, now fixed for every data tab at once
- **Fixed: the Live Prompt Viewer scrolled away from the prompt being read.** The list is newest-first, so every new prompt is **prepended** above the one you are reading; restoring a raw `scrollTop` therefore showed a different row on each poll, and the prompt under the cursor drifted down the viewport until it was gone — which reads as the viewer scrolling up on its own. The list is now anchored to the selected **row** (`data-seq` + `getBoundingClientRect`), so a repaint shifts `scrollTop` by the row's own delta and the chosen prompt stays exactly where it is. A new `livePinned` flag keeps a poll from undoing a click: an unpinned viewer follows the live tail (newest selected, list at the top, which is what you want when you open the tab mid-run) and a click or a scroll pins it. The prompt body beside the list keeps its own place too, keyed by `live-preview-<seq>`, so a repaint of the same entry does not scroll a long prompt back to the top while a click on a different entry starts at the top
- **No config key changed and nothing about what is sent to an API or written to an output file changed**, so a default run is byte-identical to v16.0.1. This is a browser-side change only: `webapp/static/js/tabs.js`, its tests and its docs
### v16.0.1
- **Fixed: `python -m webapp` died on Windows before it started** — `AttributeError: module 'socketserver' has no attribute 'ThreadingUnixStreamServer'`, raised from `control.py`'s module scope. Windows has no `socket.AF_UNIX` at all, so `socketserver` never defines its unix server classes there, and naming `socketserver.ThreadingUnixStreamServer` in a `class` statement executes that attribute lookup at **import** time on every platform, whether or not a unix socket is ever opened. The class is now defined only where the address family exists, so the whole chain (`control`, `cli`, `run_config`, `generation`, `quality`, `webapp`) imports on Windows
- **The control channel is genuinely cross-platform, not merely importable** — the local channel is a **unix domain socket on Linux and macOS** and a **loopback TCP listener on Windows**. On Windows the listener binds `('127.0.0.1', 0)` — an ephemeral port chosen by the OS, never a fixed number, so two controllers cannot collide — and **publishes** it in a JSON endpoint file at `socket_path` (`{"transport": "tcp", "host": ..., "port": ..., "pid": ...}`). `control.read_endpoint()` / `write_endpoint()` / `remove_endpoint()` own that file boundary, and `send_request()` / `is_server_running()` read it, so `--socket PATH` names the same thing on every platform and no verb needs a Windows-specific flag. The endpoint file is also the singleton guard on both platforms: while it exists and answers, a second controller is refused with `already_running`, and a leftover from a crash is cleaned up on the next launch. `control.HAS_UNIX_SOCKETS` is the one flag; nothing above the transport branches on the OS
- **Fixed: the detached controller was not detached on Windows** — `cli._launch_daemon()` passed `start_new_session=True`, which is POSIX-only and is **silently ignored** on Windows: not an error, just no effect, so the controller stayed attached to the console that launched it and died with it. `cli._detached_kwargs()` now returns `start_new_session=True` on POSIX and `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` on Windows. `_serve()` also wraps its `signal.signal(SIGTERM, ...)` in a `try`, because a detached Windows process has no console and that call raises `ValueError`
- **A class guard against the next POSIX-only assumption** — `tests/test_cli_control.py` re-imports the whole chain in a **subprocess with `socket.AF_UNIX` deleted** (the import failure, the web-app import failure, and a full loopback-TCP round trip of the protocol), scans `control.py` / `cli.py` / `run_config.py` for POSIX-only `os` and `signal` calls, and asserts the daemon launch detaches per platform. **41 headless checks, all green**, and the full suite passes
- **No config key changed and nothing about what is sent to an API or written to an output file changed**, so a default run is byte-identical to v16.0.0. On Linux and macOS the transport is the same unix socket it always was; only the Windows path is new
### v16.0.0
- **The Tk GUI is gone. The generator has two front ends, and both drive one engine.** `python -m webapp` is the browser UI and `python -m cli` is the terminal, and neither one owns the generation code: both construct the same `control.HeadlessController` and talk to it over the same local socket. The desktop window that used to be a third front end is deleted, not deprecated — **8 modules and 13,716 lines** removed: `generate_tk.py` (4,860), `config_editor.py` (4,079), `dashboard.py` (1,403), `tools/check_gui_layout.py` (1,017), `ui_theme.py` (722), `datasets_panel.py` (696), `ui_layout.py` (494) and `dataset_column_menu.py` (445)
- **The engine is headless, and that is now enforced rather than assumed.** `generation.py` imported `tkinter as tk` for one shim, `app_state.py` held the widget handles and the `root` window, and `control.py` carried a `StaticVar` class that existed only to wrap a `tk.BooleanVar`. All three are gone. `run_config.py`, `control.py` and `cli.py` import no GUI toolkit at all, so every headless verb works with no display attached — which is what made the whole control surface testable in the first place
- **`cli launch --tk` and `_launch_tk()` are removed.** `--gui` keeps its name so scripts and `docs/cli.md` do not break, and it means "start the web UI", which is now the only GUI. The `--tk` flag, the `_launch_tk()` function and the `args.tk` branch are gone, and the missing-dependency message no longer offers `--tk` as a fallback
- **The duplication flag is a plain bool.** `app_state.master_duplication_enabled_var` was a `tk.BooleanVar` created by the GUI at build time, and `generation.py` called `.get()` on it at 7 sites. It is now `app_state.duplication_mode`, a plain bool that `control.py` sets from the **same** `api.master_duplication_mode` config key, so the value a run sees is unchanged
- **`generation.opening_mode_mismatch()` is removed.** It existed to warn the GUI about resuming a run whose opening mode had changed, and nothing headless ever called it
- **The dependencies that only the window needed are gone.** `requirements.txt` no longer pins `tk`, `ttkbootstrap` or `matplotlib`. What is left is what a run actually uses: `requests`, `python-dotenv`, `PyYAML`, `psutil`, `colorama`, `redis`, `psycopg2-binary`. The web UI's own dependencies stay in `requirements-web.txt`, so a headless install does not pull a server it will never start
- **17 Tk-only test suites are deleted and 11 are repaired.** The deleted ones tested widgets, not behaviour: the dashboard tabs, the dataset column menu, the datasets panel, the editor readability pass, the metrics tab, the missing-quotations panel, the quality-judge settings panel, the questions dataset panel, the regex watch tab rev and panel, the repeat-opener and repeat-reply panels, the review tab, the scene-cast settings panel, the style variable panel, the theme and the user emotional states panel. The 11 that read a retired module now read the module that actually owns the code — `control.py` for the worker launch, the slop gate, the style deck, the async-judge wiring and the duplication flag, and `run_config.py` for the config round trip. **59 test files and 1,045 test functions, all green**
- **The guards that named a dead module now assert the invariant they were protecting.** A test that asserted `generate_tk` was not in `sys.modules` passed for the wrong reason once the module was deleted — it would have passed whether or not a Tk window had come back. Those guards now assert that **no GUI toolkit is imported at all**, by `webapp/`, by a route module, by the engine seam or by a renderer, so reintroducing one fails the suite instead of passing it. This is a stronger check than the one it replaces
- **Every file carries one plain AGPLv3 header.** The old header carried a paragraph about very early versions having been MIT, and the tree carried a `LICENSE-MIT` file to match. Both are gone: the licence is AGPLv3-only, the header says so in one block, and `tools/add_license_header.py` applies it to all **175 files**. The MIT wording is scrubbed from `README.md`, `CONTRIBUTORS.md`, `docs/licensing.md` and `docs/license-credits.md`
- **The documentation describes the code that ships, and only that.** `AGENTS.md` and all 17 surviving `docs/agents/` topic files are rewritten for a two-front-end tree, and the six topic files that documented the deleted window are removed with it. The user docs follow: the runtime diagram has two boxes instead of three, the module table drops the seven deleted modules, the dependency rule is "the graph is rooted at `control.HeadlessController`", and the `--tk` sentences, the "config editor tab" names and the GUI layout tool are gone. **The historical changelogs (`changelog-v11`..`v15`) are records and were not rewritten** — naming the window there is correct
- **No config key changed and nothing about what is sent to an API or written to an output file changed**, so a default run is byte-identical to v15.1.1. This was checked rather than assumed: every engine module's AST, with docstrings stripped, is identical to v15.1.1's except for the four modules above, and in those four the only executable changes are the removed `tkinter` import, the removed `opening_mode_mismatch()`, and the duplication flag that reads the same config key the old `BooleanVar` was bound to
- **The web UI is unchanged by this release.** It was already the supported front end in v15, and it is now the only one. Every screen, the Config editor, the login and the CLI still work exactly as they did, and `python -m cli status` still attaches to a running web app because the web app still owns the controller and serves the socket
